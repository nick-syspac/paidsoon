## Why

The current dashboard overview in `app/dashboard/page.tsx` tries to serve multiple jobs at once: it is a triage screen, a cash-health summary, a risk digest, and a module index. The result is a crowded flow that makes it harder to understand what requires action first and what is simply background context.

Users arrive at `/dashboard` expecting a clear operating picture. Today the page mixes urgent invoice attention, cash plan and runway status, notification summaries, and module links without a clear hierarchy. This proposal reworks the overview into a guided triage flow: action first, financial posture second, summary third, and deep-dive navigation last.

## What Changes

- **MODIFIED** the `/dashboard` overview page hierarchy to prioritise urgent attention and invoice health before broader risk or module detail
- **MODIFIED** the dashboard navigation order to reflect a product narrative instead of a module-by-module accumulation order
- **DESIGNED** a three-layer information architecture for the overview:
  1. Attention: overdue, broken promises, disputed, bounced, and action-required signals
  2. Cash posture: CashPlan, RunwayGuard, and Tax Buffer summaries
  3. Digest: Owner’s Digest and module summaries such as CommitGuard, SpendLeak, Cost Guard, and MarginGuard
- **PRESERVED** all current module pages and route structure; this change is limited to layout and ordering decisions, not business logic or data model changes
- **STANDARDISED** the user journey so the overview becomes a quick triage screen rather than a long list of module cards and status panels

## Capabilities

### New Capabilities

- `dashboard-overview-triage`: a top-of-dashboard narrative that helps users identify what needs attention before moving into deeper financial or module analysis
- `dashboard-module-priority-order`: a navigation sequence that reflects the product flow, making it easier to discover the most relevant tools in the right order

### Modified Capabilities

- `dashboard-overview-navigation`: the overview becomes a clear front door to the dashboard rather than an aggregation of unrelated subpages

## Impact

- **UI**: `app/dashboard/page.tsx` will be restructured into a clearer top-to-bottom hierarchy, while the underlying cards and summaries remain intact
- **Navigation**: `components/dashboard/DashboardNavRail.tsx` will reorder entries so they match the operating flow and product intent
- **Data**: no schema changes; this is a presentation and information-architecture change only
- **Access rules**: module visibility remains unchanged and continues to respect subscription and entitlement checks already implemented across the dashboard
- **Testing**: existing dashboard rendering and navigation checks should be updated to verify ordering and summary hierarchy, without changing actual module logic

## Current-state Findings

The overview currently aggregates these concerns in one page:

- invoice attention cards generated by `lib/dashboard/overviewCards.ts`
- cash posture summaries such as CashPlan and RunwayGuard in `app/dashboard/page.tsx`
- risk and digest sections such as Owner’s Digest, Tax Buffer, and CommitGuard
- module navigation links in `components/dashboard/DashboardNavRail.tsx`

The issue is not missing functionality; it is the absence of a coherent hierarchy. The proposed structure keeps the same data and features but presents them in the order a user actually needs them.

## Scope Note

This change is intentionally limited to dashboard structure, ordering, and content hierarchy. It does not redesign the individual module pages, alter analytics logic, or introduce new product functionality.
